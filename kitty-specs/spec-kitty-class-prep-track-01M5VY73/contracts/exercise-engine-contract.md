# Contract: exercise engines (`js/views/exercises/*.js`)

`module-view.js` mounts at most one exercise per module.

## Interface

```js
export function mount(container, exercise, ctx) → { unmount() }
// exercise: { id, type, config } from the module data
// ctx: { store, answers }   // answers already validated; may be used for tailoring config
```

- The engine renders only inside `container` and removes its listeners in `unmount()`.
- It persists through `store.setExerciseState(exercise.id, …)` (or `setChecklistItem` for the checklist) and sets `completed: true` when its completion rule is met. `module-view.js` subscribes to the store and marks the module `done` once the exercise is completed.
- It must work with keyboard only, and at 360 px width.

## Engines

| type | config | Completion rule |
|------|--------|-----------------|
| `match` | `{ pairs: [{ term, definition, whyWrong? }] }` | every term matched correctly at least once (retries allowed, wrong matches show `whyWrong`) |
| `judge` | `{ statements: [{ text, isCriterion: boolean, why }] }` | every statement judged once; feedback (`why`) shown after each judgement, right or wrong |
| `checklist` | `{ items: [{ id, label, when? }], summary: true }` | every *visible* item checked (items filtered with `appliesTo`). Unchecking an item sets `completed` back to `false`. The module status stays `done` once reached (forward-only). When `summary` is true, renders "Copy my setup summary" using `buildSummary` + `clipboard.js` |

## Scoring

The exercises are low-stakes and are not scored or locked. "Completed" means attempted to the rule above, never "passed".
